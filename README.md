# botbuilders-portal

Custom JS / CSS for the BotBuilders client portal (ClientClub / HighLevel),
versioned here and served from jsDelivr. The six portal fields hold a short
pinned loader instead of thousands of lines of pasted code.

## Deploy flow

```
edit src/  →  npm run build  →  npm run release  →  bump the @vX.Y.Z tag in the
two (or six) portal fields  →  hard refresh  →  check BB_VERSION in the console
```

Verify what the live portal is actually running, in the browser console:

```js
window.BB_VERSION   // → '1.0.0 · 2026-10-07'  — the newest file loaded
window.BB_BUILDS    // → { portal: '…', courses: '…', communities: '…' } per field
```

If `BB_VERSION` is behind the tag you pasted, the field has not been saved or
the page has not been hard-refreshed. If a key is missing from `BB_BUILDS`, that
field's loader is not pointing at this repo at all.

**Always pin a tag. Never point a field at `@main` or `@latest`.** See
[Why pinned tags](#why-pinned-tags) below.

`npm run release` = build + `npm run check` (the gate, runs BEFORE the bump so a
failure changes nothing) → bump patch version → rebuild with the new version →
commit → `git tag vX.Y.Z` → `git push --follow-tags`. Use `release:minor` /
`release:major` for bigger bumps. The working tree must be clean first (npm
enforces this). If the gate aborts, `git checkout -- .` discards the rebuilt
`dist/` and you are back where you started.

While actively iterating, paste straight into the portal field instead — zero
caching, instant feedback — then cut a tag once the change settles.

## What goes where

| Portal field | Paste this | Loads |
|---|---|---|
| Portal → Custom JS | `field-snippets/portal-js.html` | inline Bob host stub + `dist/portal.js` |
| Portal → Custom CSS | `field-snippets/portal-css.css` | `dist/portal.css` |
| Course → Custom JS | `field-snippets/courses-js.js` (raw JS loader — this field takes JS, not HTML) | `dist/courses.js` |
| Course → Custom CSS | `field-snippets/courses-css.css` | `dist/courses.css` + inline anti-flash block |
| Community → Custom JS | `field-snippets/communities-js.html` | `dist/communities.js` |
| Community → Custom CSS | `field-snippets/communities-css.css` | `dist/communities.css` |

Each snippet is a **full replacement** for its field. `field-snippets/` is
regenerated by every build with the current version baked into the URLs, so
never hand-edit the version there — bump `package.json` and rebuild.

Two things are deliberately kept inline in the snippets rather than hosted:

- **Portal JS: the Bob host stub.** The Bob widget looks for `[data-bob-embed]`
  exactly once at init. An external script arrives too late and Bob falls back
  to a floating panel. `portal.js` adopts the host the stub created.
- **Course CSS: the anti-flash block.** `@import` is async; without the inline
  rules the unstyled lesson flashes before `courses.css` lands. `@import` must
  stay the first rule in the field.

Read [CONTEXT.md](CONTEXT.md) before touching anything in `src/`. It explains
what each block does, which portal selectors it depends on, and the ways this
has already broken.

## Repo layout

```
src/              editable truth — exactly what used to live in the portal fields
                  (JS files keep their <script> wrappers; the build strips them)
dist/             build output, COMMITTED — jsDelivr serves from here, there is no CI
field-snippets/   exactly what to paste into each portal field (generated)
scripts/build.mjs the build (Node stdlib only)
scripts/check.mjs the acceptance checks, runnable
CONTEXT.md        the why behind the code
```

### What the build does

1. Strips `<script>…</script>` wrappers from `src/*.js` and concatenates the
   block bodies **in order**, separated by `/* ── block N ── */`. Order matters:
   later blocks use `window.bbGetIdentity` defined by block 1. Files with no
   `<script>` tag are passed through untouched.
2. Prepends `window.BB_VERSION = '<version> · <ISO date>'` (plus a per-file
   `BB_BUILDS` entry) to each `.js`, and the same as a comment to each `.css`.
3. Regenerates `field-snippets/` from templates with the pinned URL.
4. Runs every built `.js` through `node --check` and exits non-zero on any
   syntax error. A syntax error in a portal field takes the whole portal down.

`npm run check` then runs the seven acceptance checks from the original brief
(stamps present, parse clean, no leftover `<script` tags, stale-deploy markers
present in `dist/portal.js`, Bob stub before the loader, every URL pinned,
README first screen). `npm run release` runs it automatically before committing.

The jsDelivr repo path lives in one place: `package.json → config.cdnRepo`.

## Why pinned tags

Measured from jsDelivr:

```
@1.9.3  (pinned)   cache-control: max-age=31536000, s-maxage=31536000, immutable
@latest (moving)   cache-control: max-age=604800,   s-maxage=43200
```

A moving pointer is cached 12h at the edge and **up to 7 days in each visitor's
browser**. jsDelivr's purge endpoint clears the edge but cannot reach browsers
that already hold the file — you would see your change and members would not,
for days. A pinned tag is a new URL, so there is nothing to invalidate.

## First-time setup

1. Create the GitHub repo named in `package.json → config.cdnRepo`
   (currently `BotBuilders/botbuilders-portal`). It must be **public** for
   jsDelivr to serve it. Change `cdnRepo` if you use a different path and
   rebuild.
2. `git remote add origin git@github.com:BotBuilders/botbuilders-portal.git`
3. `git push -u origin main --follow-tags`
4. Confirm each URL in `field-snippets/` returns 200 before pasting:
   `curl -sI https://cdn.jsdelivr.net/gh/BotBuilders/botbuilders-portal@v1.0.0/dist/portal.js | head -1`
5. Paste the snippets into the fields, hard refresh, check `BB_VERSION`.

## Source provenance

`src/` holds the live field contents as of 2026-10-07, exported from the portal
admin. Two notes for anyone re-exporting:

- Files that reach disk via TextEdit tend to be saved as RTF. `courses.js` and
  `communities.js` were, and were converted back with `textutil -convert txt`,
  then checked for smart-quote damage (none) and run through `node --check`.
  `npm run check` refuses any `src/` file that is RTF.
- The exported `communities.css` was truncated at the very end: the final
  `#event-share-button` rule was missing its closing `}` and ended in a stray
  `\`. That brace was restored; nothing else in the file was changed.

## Constraints

- `src/` is the editable truth, `dist/` is build output — but **commit `dist/`**.
- Do not refactor the source files as part of a packaging change.
- Preserve `<script>` block order within each file.
- No bundler, no TypeScript, no framework. Plain files, one Node script.
